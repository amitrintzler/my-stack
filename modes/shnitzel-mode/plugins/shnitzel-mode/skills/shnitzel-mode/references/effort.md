# Outcome and effort

For implementation, keep a compact decision record in the conversation: outcome, evidence/uncertainty, minimal solution, optional broader solution and incremental benefit, verification, recommended tier. Do not write a ledger for a simple task.

A request to add a distributed cache may be solved by an existing cache, one missing index, a configuration fix, or measurement showing no change is useful. Explain the observable tradeoff. Never replace a user requirement with a cheaper but incomplete solution. After the user chooses, the decision is settled until new evidence materially changes scope.

Focused work uses the short workflow in the router. Standard/deep work delegates engineering depth to pstack's installed playbooks. Project playbook modifications must pass pstack's check-playbooks script against the installed revision. Do not load every leaf skill in anticipation. Formal verification is available for suitable invariants and explicit requests, not compulsory for ordinary edits. `/sharpen` rewrites a prompt only and does not start the task.

Resolve model roles from the current runtime's pstack-models sheet. Default deep panels to two reachable configured models. Diverse vendors are useful when available, not a reason to invent access or block a valid same-provider review. Label reduced diversity. Never lower a required independent review to self-review. A role or effort unavailable on the runtime is an explicit capability gap.

The effort gate is judgment, not a deterministic classifier. Validate it with realistic scenarios and observed actions, not keyword matching. No fixed number of changed files proves a task is simple.

Recommended effort is low for direct/focused, medium for standard and high for deep. Apply it only through an actual supported per-request or dispatch control. A standing instruction cannot change a fixed parent session model or its configured reasoning effort; do not claim that it did. Preserve explicit user model choices and use the nearest supported effort only when the runtime documents that mapping.
