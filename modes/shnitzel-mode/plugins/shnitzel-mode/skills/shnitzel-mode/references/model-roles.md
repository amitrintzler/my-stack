# Model roles

Use pstack's runtime-specific pstack-models.md, as located by the installed setup-pstack skill. Shnitzel does not own a competing universal role sheet. Configure only reachable models and accepted effort levels; preserve user choices during upgrades.

The installer imports a legacy model-roles.md as a proposal and keeps the original. Map executor to feature/refactoring, fast to routine workers, judgment to judgment/prose and the other single-model roles, panel to panel lists. These are proposals until model availability is confirmed in that runtime. Do not overwrite an existing pstack sheet with a legacy mapping.

Focused work stays in the current session without spawning a cheaper model just to save tokens. Standard work uses required workflow roles. Deep review defaults to two configured reachable reviewers. Role changes are persistent only when the user asks for configuration changes; per-task changes remain task-local.
