# Capabilities and limits

Shnitzel 1.4 adds effort admission, meaningful approach selection, isolated upstream updates and explicit budget capability checks. Thirty optional operational skills and seventeen domain cards remain available. Ordinary questions and focused edits bypass the full pstack router.

The engine lock records exact released-port and original-pstack revisions, included upstream changes and runtime exclusions. Updates validate before activation and retain the previous engine. Runtime model choices use pstack's per-runtime sheets.

The watch digest distinguishes incomplete collection from observed empty data. It reports pending checks separately from green, and supports no-state observation. Scheduled work remains read-only.

BudgetLedger offers atomic reservations to a host that controls all model requests. Native CLI or Cowork hard-budget enforcement is not verified and is rejected on explicit hard-cap requests. Usage reports distinguish measurements, estimates and unknowns. No dollar-cost equivalence is assumed for subscriptions or local inference.

See [runtime adapters](docs/runtimes.md) and [acceptance](docs/acceptance.md) for detected, contract-tested and live-verified status. Skill prose alone is not an enforcement boundary. Supported installation is not equivalent to successful live acceptance or demonstrated token savings.
